# S07 — Account lifecycle and hardening

## Outcome

Users can securely delete their account, revoke current credentials, and leave no linked history; a later sign-in may create a fresh unrelated account.

## Entry criteria

S06 is merged and closed by the first transition commit on `feature/ios-account-lifecycle`; S07 is the only `in_progress` slice.

## Scope

Implement re-authentication as required, destructive confirmation, deletion progress/failure/recovery, local credential/data purge, provider revocation where supported, backend unlink/anonymization/deletion rules, and privacy/security hardening.

## Public contracts

Add `DELETE /api/v1/users/me`. It revokes existing credentials and unlinks deleted history. It must not permanently bind the external identity to a tombstone: a future sign-in creates a fresh account with no relationship to the deleted account.

## UX and state contract

Use explicit destructive copy, non-color warning iconography, required confirmation/re-auth, disabled duplicate action, retryable failure, successful return to login, VoiceOver announcements/focus, Dynamic Type, and both appearances.

## Architecture and tests

Inject account repository, auth provider revoker, token/local-data stores, and clock. Unit/integration tests prove credential invalidation, unlinking, idempotency, retained aggregate privacy, and fresh unrelated re-registration; UI tests cover cancel, re-auth failure, server failure, and success.

## Exclusions

App Store signing/publication and unrelated product expansion.

## Verification evidence

Record iOS/backend suites, `.xcresult`, JUnit, database/API assertions with synthetic data, deletion screenshots, and privacy/secret scans.

## Exit criteria

Deletion is secure, recoverable before confirmation, deterministic after success, and proven not to reconnect a later account to deleted history.

## Next transition

Create `feature/ios-release`; record S07 PR/merge evidence, mark S07 `done`, and start S08.
