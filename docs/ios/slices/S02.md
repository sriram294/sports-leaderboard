# S02 — Groups and app shell

## Outcome

Authenticated users enter the native tab shell and can create, join, select, rename, invite to, manage, or leave groups according to role.

## Entry criteria

S01 is merged and closed by the first transition commit on `feature/ios-groups-shell`; S02 is the only `in_progress` slice.

## Scope

Build native navigation/tab composition, selected-group persistence, group switcher, create/join/invite flows, member/role management, and session-to-shell routing using existing APIs.

## Public contracts

No planned backend endpoint changes. Preserve current group DTOs, invite semantics, and owner/admin/member permissions.

## UX and state contract

Cover first-group empty state, loading skeletons, retryable failures, stale/offline selection, destructive confirmations, role-denied messaging, share-sheet permission behavior, accessibility actions, Dynamic Type, and light/dark appearance.

## Architecture and tests

Group Screen/ViewModel/State and repository protocol groupings receive API, selected-group store, clock, and sharing adapter through injection. Unit tests cover permission matrices and selection changes; UI tests cover creation, joining, switching, editing, and empty/failure states.

## Exclusions

Leaderboard data, match history/recording, profile/stats, notifications, and account deletion.

## Verification evidence

Record Xcode/backend commands, `.xcresult`, JUnit, API tests, and screenshots for roles and states.

## Exit criteria

All role-appropriate group actions and shell navigation work with deterministic state restoration and accessibility checks.

## Next transition

Create `feature/ios-leaderboard`; record S02 PR/merge evidence, mark S02 `done`, and start S03.
