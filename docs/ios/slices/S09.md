# S09 — Team-v2 leaderboard parity

## Outcome

The native iOS leaderboard consumes the versioned team-v2 contract and presents
the same cumulative Skill rating, qualification boundary, canonical ordering,
and provisional treatment as Android and PWA.

## Entry criteria

S08 is merged and closed. The team-v2 backend and the Android/PWA parity work
are merged in PR [#126](https://github.com/sriram294/sports-leaderboard/pull/126),
with the caption cleanup merged in PR
[#127](https://github.com/sriram294/sports-leaderboard/pull/127).

## Scope

- Decode optional `algorithmVersion`, `ratingPeriod`, `uniquePartners`,
  `maxPartnerShare`, `provisionalReason`, and `limitedPartnerVariety` fields
  safely, including legacy Wilson/team-v1 responses.
- Keep Skill rating cumulative through the evaluation cutoff while the selected
  This Month/All Time range controls statistics, recent form, streaks, and
  qualification.
- Render qualified entries under **Rankings** and provisional entries under
  **Not yet ranked**, with muted provisional values, no numbered rank, and the
  existing “N more to rank” progress caption.
- Preserve server order for Skill rating, stable in-section metric sorting,
  canonical qualified podium order, and qualified-only sharing.
- Keep the board free of explanatory model, threshold, and partner-variety
  subcaptions; `limitedPartnerVariety` remains an informational API field.

## Public contracts

`GET /api/v1/groups/{groupId}/leaderboard` returns `team-v2`/
`cumulative` metadata at response and entry level when the feature flag is on.
The fallback with `PLAYBOARD_TEAM_V2_ENABLED=false` remains decodable and
retains the legacy win-rate explanation. Ratings are displayed to one decimal;
the server owns canonical ordering and sequential API ranks.

## UX and state contract

Support loading, empty, failure, refresh, This Month, All Time, large Dynamic
Type, VoiceOver, light/dark appearance, and legacy payloads. Provisional rows
are visibly separated but remain selectable. Do not imply that partner variety
is required to qualify.

## Architecture and tests

Keep the existing Swift 6 MVVM/Repository boundaries and initializer-injected
dependencies. Add deterministic decoding and view-model tests for optional
fields, cumulative range mapping, provisional sections, rounded display ties,
podium/share exclusions, and legacy fallback. Record Xcode 26.2 simulator build,
test, and light/dark screenshot evidence when macOS access is available.

## Exclusions

No new endpoint, schema migration, persistent iOS rating calculation, or store
publication. The client does not reimplement server ranking or recompute skill.

## Verification evidence

Linux repository/static checks and the Android/PWA suites are recorded in the
implementation PRs. Xcode 26.2 build, test, accessibility, and screenshot
artifacts are still pending on macOS and must be added before S09 can close.

## Exit criteria

The iOS client decodes both team-v2 and legacy payloads, matches Android/PWA
sectioning and sharing behavior, and has durable Xcode 26.2 build/test and
large-text/light-dark screenshot evidence. The next transition commit may then
mark S09 `done`.
