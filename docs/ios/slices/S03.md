# S03 — Leaderboard

## Outcome

Group members see the branded podium and complete rankings for exactly `This Month` and `All Time`.

## Entry criteria

S02 is merged and closed by the first transition commit on `feature/ios-leaderboard`; S03 is the only `in_progress` slice.

## Scope

Implement Board Screen/ViewModel/immutable State/repository, range selection, refresh, podium/rank rows, avatar fallbacks, and monthly recognition using the existing leaderboard window contract.

## Public contracts

No API expansion. Range values remain month/all-time only; do not add week, year, or arbitrary dates.

## UX and state contract

Cover loading, no matches, no members, partial avatar failures, stale/offline data, request failure/retry, pull-to-refresh, accessibility value summaries, tabular figures, Dynamic Type alternatives for dense rows, and both appearances.

## Architecture and tests

Inject leaderboard repository and clock/calendar so month boundaries are deterministic. Unit-test sorting, ties, range state, cancellation, and response mapping. UI tests and screenshots cover podium, dense lists, empties, and errors.

## Exclusions

Match detail/recording and image sharing.

## Verification evidence

Record Xcode commands, `.xcresult`, JUnit, API contract checks, and reference-comparison screenshots for both ranges and appearances.

## Exit criteria

Month/all-time data and every required state match the contract, remain accessible at supported Dynamic Type sizes, and pass deterministic tests.

## Next transition

Create `feature/ios-matches`; record S03 PR/merge evidence, mark S03 `done`, and start S04.
