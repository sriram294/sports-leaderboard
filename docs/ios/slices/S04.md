# S04 — Matches and recording

## Outcome

Members browse match history/details and authorized users record a validated match with native interaction patterns.

## Entry criteria

S03 is merged and closed by the first transition commit on `feature/ios-matches`; S04 is the only `in_progress` slice.

## Scope

Implement match list/detail and add-match feature groupings, player/team selection, score validation, optimistic/submitting states, idempotent retry behavior, and list refresh using existing APIs.

## Public contracts

No planned backend endpoint change. Preserve current record-match DTO, authorization, scoring, and returned rating-delta semantics.

## UX and state contract

Cover list loading/empty/error/offline, expanded details, form validation, keyboard/focus, accidental-dismiss confirmation, duplicate submission protection, authorization denial, success feedback, VoiceOver ordering, Dynamic Type, and light/dark screenshots.

## Architecture and tests

Inject match repository, group membership source, clock, and request-ID generator. Unit-test score/team rules and submission races; UI tests exercise browse, expand, invalid form, success, and retry; backend tests protect rating calculations and idempotency.

## Exclusions

Profile editing, statistics, sharing, notifications, and deletion.

## Verification evidence

Record iOS/backend suites, `.xcresult`, JUnit, request fixtures, and screenshots of major states.

## Exit criteria

History and recording are complete, permission-aware, duplicate-safe, accessible, and compatible with existing clients.

## Next transition

Create `feature/ios-profile-stats`; record S04 PR/merge evidence, mark S04 `done`, and start S05.
