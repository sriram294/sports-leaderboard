# S01 — Authentication and session

## Outcome

Users sign in natively with Google or Apple, restore/refresh a session, see deterministic recovery states, and sign out.

## Entry criteria

S00 is merged; the first `feature/ios-auth` commit records its PR/merge evidence and transitions S00 to `done` and S01 to the only `in_progress` slice.

## Scope

- Initialize configured Google Sign-In and implement Sign in with Apple using AuthenticationServices.
- Add login Screen, `@MainActor` ViewModel, immutable state/actions, auth repository, secure token storage, refresh, restore, and logout.
- Add provider-neutral backend identity support and integration tests.

## Public contracts

Add `POST /api/v1/auth/apple`. Extend user/session responses with provider-neutral `authProviders` without breaking existing Android/PWA clients. Configuration remains environment-injected; no secret enters source control.

## UX and state contract

Native provider buttons, progress, cancellation, offline/failure recovery, expired-session routing, VoiceOver labels, Dynamic Type, light/dark screenshots, and usable error actions. Provider availability is never communicated by color alone.

## Architecture and tests

Inject auth provider adapters, repository, token store, clock, and API client. Unit-test every state transition and refresh race; backend tests cover linking/uniqueness; UI tests cover success fakes, cancellation, failure, restore, and logout.

## Exclusions

Groups, main tab shell, push token registration, and account deletion.

## Verification evidence

Record affected Android/backend/iOS commands plus `.xcresult`, JUnit, API integration results, and login screenshots without personal data.

## Exit criteria

Both providers, restore, refresh, and logout pass deterministic tests; legacy clients remain compatible; configuration absence fails safely; no credentials are committed.

## Next transition

Create `feature/ios-groups-shell`; record S01 PR/merge evidence, mark S01 `done`, and start S02.
